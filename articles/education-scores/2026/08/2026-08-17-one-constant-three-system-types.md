# 只改右边一个数，答案从无穷多个变成没有：方程组先分类

看这两行：

```text
2x + 3y = 13
4x + 6y = 26
```

第二行正好是第一行的两倍，所以它没有提供新约束。把最后的 26 改成 27，左边仍说“完全相同的直线”，右边却要求它同时落在另一个位置。只改一个常数，答案就从无穷多个跳到一个也没有。

这比求出 `x`、`y` 更值得先看：线性方程组的第一问应当是“有几个解”，确认唯一后才轮到具体数值。

## 用三个秩条件分流

把二元系统写成矩阵形式：

```text
A = [[a, b], [d, e]]
b = [c, f]
A · [x, y]ᵀ = b
```

系数矩阵的秩记为 `rank(A)`，把右边常数列接上得到增广矩阵 `[A|b]`。对于两个未知数，分类规则是：

```text
rank(A) = rank([A|b]) = 2  → 唯一解
rank(A) = rank([A|b]) < 2  → 无穷多个解
rank(A) < rank([A|b])      → 无解
```

它们分别对应两条直线相交、重合和平行但不重合。OpenStax 从图形、代入与消元三种角度给出了同一分类；矩阵秩只是把这件事压缩成可复核的结构证据。

## 第一组：行列式不为零，先锁定唯一性

取：

```text
2x + 3y = 13
4x −  y = 5
```

二阶系数行列式为：

```text
D = a·e − d·b
  = 2×(−1) − 4×3
  = −14
```

`D ≠ 0`，两行系数不是倍数，唯一解已经确定。再消元：把第一式乘 2，得到 `4x+6y=26`；减去第二式，`7y=21`，所以 `y=3`。代回 `4x−3=5`，得到 `x=2`。

双重反查：

```text
2×2 + 3×3 = 13
4×2 − 3   = 5
```

我把六个系数输入 [CalculatorQueen 方程组计算器](https://calculatorqueen.com/calculators/system-of-equations-calculator)，页面返回 `x=2; y=3`、两种秩都为 2，并显示 RREF 为 `[1,0|2]`、`[0,1|3]`，与手算一致。

## 第二组：整行成倍，留下自由变量

把第二式改为：

```text
4x + 6y = 26
```

它等于第一式的两倍，消元后出现零行：

```text
[0, 0 | 0]
```

这个零不是一个新的方程，而是“第二条信息完全重复”。页面把它分类为无穷多个解，显示 `rank(A)=rank([A|b])=1<2`，并指出仍有自由变量。可以令 `y=t`，则 `x=(13−3t)/2`；每个允许的 `t` 都产生一组解。

只报告 `x=2,y=3` 在这里是不完整的。它确实是其中一个解，却没有说明同一条直线上的其余点也全部满足系统。

## 第三组：只把 26 改成 27

现在保留左边的倍数关系，却写成：

```text
4x + 6y = 27
```

第一式乘 2 后仍是 `4x+6y=26`，与第二式相减得到：

```text
0x + 0y = 1
```

这是矛盾行 `[0,0|1]`。系数矩阵仍只有一个独立方向，`rank(A)=1`；常数列把增广矩阵的秩抬到 2，所以没有任何 `x,y` 能同时满足两式。页面也返回 No solution，并明确显示 `rank([A|b])=2>rank(A)=1`。

这一组揭示了为什么不能只看系数。第二、三组的系数矩阵完全一样，差别只在右边常数；若忽略增广列，就分不清“同一条线”和“两条平行线”。

## 把 RREF 当成收据，而不是黑盒装饰

结果卡片上的分类词可以抄错，最终行最难撒谎。唯一解的 RREF 在变量列形成单位矩阵，每个主元直接指向一个变量值；无穷解保留至少一个没有主元的变量，并出现合法零行；无解则一定能看到系数全零、右边非零的矛盾行。

行交换、用非零常数缩放整行、把一行的倍数加到另一行，都保持原系统的解集。复核时可以从原增广矩阵重做一条短消元链，而不必机械复制计算器的每一步。若最终写出 `[1,0|2]` 与 `[0,1|3]`，还要把 2、3 代回原方程；RREF 核对运算过程，代回核对抄录和变量顺序，两道门负责不同错误。

三元系统也是同一逻辑，只是系数列增加到三个。`rank(A)=rank([A|b])=3` 才能给出唯一三元组；共同秩低于 3 就有自由变量。看到三个方程并不保证三条独立约束，因为其中一行仍可能由另外两行线性组合得到。

## 小数系统要保留比例证据

计算器接受整数、小数、零和科学记数法，并用 Gauss–Jordan 消元及相对零阈值处理浮点输入。非常接近倍数的两行，可能代表真实的微小差异，也可能只是测量或录入舍入。软件必须选阈值，读者则必须查看原始精度和量纲。

例如把 6 写成 `6.0000000001`，行列式虽非零，理论上会得到唯一解，却可能对输入扰动极敏感。不要仅凭界面给出两个很长的小数，就断言模型稳定；应缩放单位、保留原始数据并检查代回残差。

还有三个边界：本工具只处理有界的 2×2 和 3×3 实系数线性系统；缺失变量必须显式填 0，不能让后续系数错位；若题目要求票数、人数等非负整数，代数解还要通过语境约束，不能把负数或小数自动解释成可行方案。
