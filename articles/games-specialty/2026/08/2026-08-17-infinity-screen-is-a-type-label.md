# 屏幕上的 ∞ 到底是什么：先给计算器结果贴对类型标签

有些计算器小把戏最会制造错觉：按下 `8 ÷ 0 =`，屏幕亮出一个 ∞，仿佛刚刚把“除以零”这条禁令按没了。

结论先放桌上：这个符号可以是软件数值类型按约定返回的状态，却不是普通实数除法突然有了答案。真正值得做的实验，不是追问“怎样按出无穷”，而是给屏幕信息分类：它究竟表示软件的 Infinity 值、未定义运算、有限数溢出，还是函数的无界趋势？

## 从一条最朴素的等式开始

设被除数为 `n`，除数为 `d`，商为 `q`。在实数算术里，`n ÷ d = q` 的意思是：

```text
d × q = n
```

当 `n = 8`、`d = 0` 时，不论把哪个有限实数放进 `q`，左边都是 0，不可能等于 8。因此 `8 ÷ 0` 没有实数商。

`0 ÷ 0` 又是另一种失败：这次每个 `q` 都满足 `0 × q = 0`，条件无法挑出唯一答案。前者是没有可选商，后者是候选太多而无法决定。把二者都随手写成 ∞，相当于把两种不同的错误揉成一团。

## 三次按键，得到三种可核对的状态

我在 [CalculatorQueen 的无穷显示实验页](https://calculatorqueen.com/calculators/calculator-infinity-trick) 依次清空输入，并只改变一个条件。实测结果是：

- `8 ÷ 0` 显示 `∞`，同时明确提示这是本页的显示约定；
- `−8 ÷ 0` 显示 `−∞`，符号随有限非零被除数改变；
- `0 ÷ 0` 不显示带符号的无穷，而报告未定义且不定。

这三个输出和页面声明一致，也能用前面的乘法反查。尤其是第二次测试，它说明屏幕保存的不只是“数很大”这个模糊感觉，而是采用了带正负号的特殊值约定。

ECMAScript 的 `Number` 是有限精度软件类型，规范为它定义了 `Infinity`、`−Infinity`、`NaN` 和带符号的零。有限非零 Number 除以零时，可以按操作数符号返回带符号 Infinity。这里的重点是“该类型规定如何返回”，不是“实数体系证明了一个新商”。

## 1E99 也不能偷偷升级

一些 TI-83、TI-84 工作流会用 `1E99` 或 `−1E99` 充当计算范围端点。它们分别是 `1 × 10^99` 和 `−1 × 10^99`，每一位含义都仍然有限。它可以在设备允许的任务里近似代表“非常远”，却没有资格成为最大的实数——给它再加 1，仍然得到一个更大的有限数。

这也解释了为什么“溢出”不能自动翻译成数学无穷。比如 `10^10000` 是一个确定的有限整数；浏览器 Number 若装不下，暴露的是表示范围不足。仓库放不下整本书，不等于那本书有无限页。

## 极限中的无穷是方向说明

再看函数 `f(x)=1/x`。当 `x` 从正侧逼近 0 时，函数值可以超过任意预先选定的正界；从负侧逼近时则向负方向无界。这里讨论的是一串允许输入的行为：

```text
x → 0+ 时，1/x → +∞
x → 0− 时，1/x → −∞
```

它不是把 `x=0` 塞进公式后得到一个普通函数值。OpenStax 对无穷远极限和渐近线的处理，正是把“趋近时无界”与“点上有值”分开。左右方向不同，也是不能用一次非法代入代替极限分析的直接证据。

## 一张可复用的判别清单

下次看到 ∞，先问四件事。

第一，原表达式的定义域是否允许这次输入？若分母就是 0，先停止普通实数运算。

第二，工具文档是否声明了软件约定？若它使用 IEEE 风格或 ECMAScript Number 语义，应把结果记成“特殊值”，不要抄成精确实数商。

第三，原问题是否其实是极限？那就必须写明从哪一侧、哪个变量怎样趋近，不能只留一个孤零零的 ∞。

第四，是否只是有限表示溢出或设备端点？记录真实表达式和精度范围，别把 `1E99`、`9.99E307` 一类有限标记冒充数学对象。

为了让别人能复现，还应把计算器名称、模式、清空状态、完整按键顺序和提示文字一起保存。只截取结果框里的 ∞ 会丢掉最关键的上下文；同一串字符在实数教材、浏览器控制台和手持设备上，可能分别得到“未定义”、特殊值或错误信息。差异本身不是谁算错了，而是三者回答的类型问题不同。

还有一个操作边界：实验页把 ∞ 设成终止结果，不允许把它存进内存继续连算。这个限制很有价值，因为 `∞−∞`、`0×∞` 等形式需要看原问题的生成过程；只拿两个显示符号做普通代数，极容易制造第二轮误判。
